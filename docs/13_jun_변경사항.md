## 1. AG-T54 요청 종류 판정률 평가

`agent/knowledge.py`의 시스템 프롬프트로 고객 요청을 맞게 가려 맞는 행동을 했는지 잰다. 응대 점수(채점 AI)와 따로 본다.

### 파일

| 파일 | 내용 |
|---|---|
| `scripts/intent_eval.py` | 평가 도구(새) |
| `data/eval/request_types.json` | 공식 연습 80문항의 요청 종류·허용 행동 라벨(새) |
| `data/eval/haruon200/cases.jsonl` | 녹음 대본(`recording_script_1.pdf`) 200문항을 공식 연습 문항 형식으로 옮긴 것(새) |
| `data/eval/haruon200/labels.json` | 위 200문항의 라벨(새) |
| `tests/test_intent_eval.py` | 행동 분류기 테스트(새) |

### 동작

1. `scripts/text_eval.py`의 `run_case`로 한 턴을 돌린다. 실제 서버와 같은 프롬프트(`knowledge.build_system`)·응답기·함수 검사·모의 함수를 쓰고 STT·TTS만 건너뛴다.
2. 그 턴의 행동을 하나로 분류한다(우선순위 순).
   - 접수 함수를 실행했으면 `ACT:<함수>`
   - 조회·검색을 실행했으면 `LOOKUP_ORDER` / `LOOKUP_RETURN` / `SEARCH`
   - 말만 했으면 내용으로 `HANDOFF`(상담원 연결) / `ASK_ID`(주문번호·연락처) / `ASK_PRODUCT`(어떤 제품) / `CLARIFY`(용건) / `ASK_DETAIL`(그 밖의 질문) / `ANSWER`(안내)
   - 말은 마지막 질문 문장으로 정한다. 정책 등을 실제로 안내한 문장(공감·사과 제외 25자 이상)이 있으면 `ANSWER`도 맞은 것으로 본다.
3. 라벨의 허용 행동과 비교해 전체 판정률, 요청 종류별 정확도, 틀린 행동 표, 틀린 문항(고객 말·호출·발화)을 `runs/intent/<이름>/report.md`로 낸다.

분류기 검증: 연습 80문항의 실제 상담 답에 돌리면 79/80이 라벨과 같다(나머지 1개는 "안녕하세요"에 "감사합니다"로만 답한 실제 상담 쪽 문제).

### 라벨 기준

- 연습 80문항: 실제 상담 답을 기본으로, 규칙상 다른 행동도 맞는 경우(예: 발신자 번호가 있으면 묻지 않고 조회)는 함께 허용했다.
- 녹음 대본 200문항: 대본의 시나리오 분류(배송·주문확인 30, 배송지변경 10, 오배송·누락·미수령 14, 상품문의·추천 26, 주문취소 18, 반품·환불요청 26, 반품·환불진행 16, 교환·불량 12, 결제·전화주문 22, 상담원연결·기타 26)를 요청 종류로 쓰고, 허용 행동은 시나리오와 브랜드 정보로 정했다.
  - 현재 시각은 2026-11-24(화) 10:30(대본의 "11월 24일 주문·출고 전"에 맞춤).
  - 등록 고객은 발신자 정보에 이름과 가상 번호를 넣었다. 모의 DB에 이 고객들의 주문이 없어 조회는 `not_found`가 나오므로, 이전 대화에 주문번호가 없는 접수 문항은 조회도 맞은 것으로 본다.
  - 녹음 음성은 아직 없어 글 그대로(`--source original`)만 된다.

## 2. AG-T55 소음 속 말 끝

### 문제

주변 소음(특히 사람 말소리·TV)이 있으면 말 끝이 확정되지 않았다.

- 침묵은 VAD 확률이 임계(0.5) 미만인 프레임으로만 쌓이고, 음성 프레임 하나(20ms)에 0으로 돌아간다. 주변 말소리는 Silero가 음성으로 보므로 침묵이 400~1100ms까지 쌓이지 못하고, 확정이 안전 상한(20초)까지 밀린다. 첫 소리 6초 초과면 속도 0점, 25초 안에 `turn.end`가 없으면 문항 실패.
- 기존 `NoiseGate`(AG-T10c)는 말소리형 잡음 판정을 통화 첫 200ms 에너지 출렁임으로만 해서 통화 중에 생긴 소음을 놓치고, 엄격 판정의 음성 유지 기준이 잡음 바닥 + 3dB라 손님보다 12dB 작은 말소리도 음성으로 남는다.

### 바꾼 것 (`agent/session.py` `_process_frame`, `agent/config.py`)

| 설정(환경변수 `DIRECTON_<대문자>`) | 기본값 | 동작 |
|---|---|---|
| `resume_min_ms` | 100 (켬) | 침묵이 시작된 뒤 음성이 100ms 넘게 이어져야 말이 다시 시작된 것으로 본다. 더 짧은 소리는 침묵으로 세고, 그동안은 확정 판단을 보류한다. 0이면 이전 동작 |
| `text_stall_cap_ms` | 3000 (켬) | VAD는 음성인데 받아쓰기 글이 3초 동안 그대로면(글이 있을 때만) 받아쓰기 끝맺음을 요청하고 최대 300ms 뒤 확정. 깨끗한 음성은 말하는 동안 글이 계속 바뀐다. 0이면 끔 |
| `text_stall_end_ms` | 0 (끔, 제안 1500) | 글이 이만큼 멈추면 그때부터를 침묵(200ms부터)으로 보고 기존 결정기 규칙으로 확정 |
| `speaker_gate_db` | 0 (끔, 제안 12) | 손님 목소리 크기(확실한 음성 프레임 에너지의 75분위, 최근 3초)보다 이만큼 이상 작은 음성 프레임은 침묵으로 본다 |
| `speaker_gate_min_ms` | 600 | 위 목소리 크기를 믿기 시작하는 최소 누적 음성 |

- 끼어들기 감지(`_watch_barge_in`)는 바꾸지 않았다.
- 글 멈춤 확정으로 이미 선호출을 시작한 뒤 음성이 이어져도 선호출을 취소하지 않는다.
- 측정 전이라 위험이 낮은 두 개(`resume_min_ms`, `text_stall_cap_ms`)만 기본으로 켰다.

### 테스트 (`tests/test_noise_endpoint.py`, 8개)

- 40ms 소리는 침묵으로 세어 원래 시각에 확정 / 스위치를 끄면 이전 동작
- 100ms 넘게 이어진 말은 그대로 재개
- 소음이 계속되면 글 멈춤 상한이 없을 때 소음이 그칠 때까지 확정 못 함(문제 재현) / 상한 3초면 약 3초 뒤 확정하고 끝맺음을 요청
- 글 멈춤 + 결정기 규칙으로 확정
- 20dB 작은 소리는 목소리 크기 기준을 켜면 침묵, 기본(끔)은 음성

### 남은 일

- 잡음을 입힌 음성(white·babble, SNR 지정)으로 오프라인 비교: 말 끝 전 확정, 놓침, 지연 p50·p95, 확정 6초 초과 비율. 그 결과로 `text_stall_end_ms`·`speaker_gate_db` 기본값을 정한다.
- 실제 소음 환경(데모)에서 확인.

## 3. AG-T56 번호 되묻기·응답 지연 (데모 피드백)

### 문제 (데모 기록 `DEMO-20261121-165416-mm6k`)

- 받아쓰기 "010. 2215. 7723이요."는 맞았는데 LLM이 번호 없이 조회를 불러 검사에 막혔고, "번호가 잘 안 들렸어요. 한 자리씩 또박또박…"으로 되물었다.
- 함수 결과 뒤 "확인해 보니 조회되는 내역이 없어요." 다음에 채움말 "확인해 드릴게요, 잠시만요."가 또 나갔고, 이어 LLM 2.8초 + TTS 첫 바이트 3.5초를 기다렸다. 문장 TTS 첫 바이트는 턴마다 3.0~3.5초.

### 바꾼 것

| 설정 | 기본값 | 동작 |
|---|---|---|
| (검사) | 항상 | 조회 함수에 번호가 없으면 이번 고객 말에서 형식에 맞는 번호 하나를 찾아 채운다 |
| `confirm_heard_number` | 켬 | 조회가 번호 문제로 막혔거나, 이번에 들은 번호로 주문 조회가 not_found면 LLM 대신 "제가 들은 번호는 공일공, 이이일오, 칠칠이삼입니다. 맞으실까요?"로 묻고 턴을 끝낸다. 직전에 이미 물었으면 하지 않는다. 반품 현황(not_found)은 되읽지 않는다 |
| (채움말) | 항상 | 결과 문구를 냈으면 채움말을 내지 않는다 |
| `answer_cache` / `answer_phrases` | 켬 / 4문장 | 답 문장이 캐시 문구와 같으면 TTS 없이 바로 낸다. 서버 시작 때 "주문번호나 주문하신 분 연락처를 말씀해 주시겠어요?" 등 4문장을 미리 합성 |

테스트: `tests/test_number_confirm.py` 9개.

### 남은 일

- 지연의 대부분은 TTS 첫 바이트다. `.env`에 `GEMINI_TTS_MODEL=gemini-3.8-flash-lite-tts`(행사 지정 모델)를 넣어 게이트웨이에서 되는지·빨라지는지 확인.
